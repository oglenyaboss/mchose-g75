# mchose-g75

Реверс-инжиниринг клавиатуры MCHOSE G75 Pro и нейро-предиктор следующей буквы, живущий в её подсветке. Протокол вскрыт из исходников официального веб-драйвера, без сниффера. Сверху подсветки работает мини-GPT, обученный с нуля: pretrain на публичных корпусах, SFT на собственном логе печати.

**[Живой кейс](https://oglenyaboss.github.io/mchose-g75/)**: интерактивная 3D-клавиатура, карта внимания модели и история всего проекта в одном iframe.

## Зачем это всё

Хотелось пройти полный цикл современного LLM руками: pretrain, SFT, RL. Не на учебном датасете, а на вещи, которая отвечает с каждого нажатия. Клавиатура подсвечивает топ-3 кандидата на следующую букву, ты печатаешь дальше, и это одновременно награда и новый обучающий сигнал. Подсветка тут транспорт, предикт содержимое, а весь код можно читать и ломать.

Побочный результат оказался ценнее плана: у этой прошивки есть единственный реалтайм-канал подсветки, про который не написано нигде, и он не лагает при печати. Обычные DIY-команды дают плавающую латентность, рука её чувствует. Музыкальный оверлей кладёт кадр в буфер, не блокируя опрос матрицы, и на нём держится всё живое в этом репо.

## Три инструмента

| Файл | Что делает |
|---|---|
| `node ripple.cjs` | Риппл: вспышка нажатой клавиши гаснет шлейфом. 25 fps, печать не лагает |
| `node lamp.cjs` | Лампа: огонь по нижнему ряду, цвет от скорости печати, грелка клавиш (нажатые греются, остывают минуты), волна при смене раскладки EN/RU. Простой на 15 секунд перетекает в огонь |
| `node candle.cjs` | Свечка: на каждом нажатии модель ONNX даёт топ-3 следующих символа. Клавиши-кандидаты горят цветом по рангу, яркость по вероятности. 8.8 мс инференс на окне 256 символов |

К каждому инструменту приложен браузерный экран: `node candle.cjs --mirror` поднимает 3D-доску, где цвет каждой клавиши это ровно тот кадр, который уходит в железо. Что горит на столе, то и на экране, рядом лог предикта с вероятностями.

Сбор данных честно вынесен отдельным файлом. `keylog.cjs` пишет ваш собственный лог нажатий в локальный `corpus/personal.log`: серии цифр схлопываются в `<num>`, Cmd/Ctrl-комбинации не пишутся, пауза по Ctrl+Alt+K. Лог никуда не отправляется, читает его только ваш пайплайн обучения.

## Быстрый старт

Нужны macOS, node и клавиатура MCHOSE G75 Pro (или AULA F75, это одно и то же устройство, см. дисклеймер).

```bash
npm install
swiftc macos/keytap.swift -o keytap
node ripple.cjs
```

`keytap` слушает нажатия глобально, ему нужен доступ в System Settings → Privacy → Accessibility. Подпись ad-hoc, грант переживает перекомпиляцию.

Важно: Bluetooth-путь на macOS закрыт системой, клаву не отдать стороннему процессу, пока bluetoothd держит её как клавиатуру. Рабочая схема это USB-кабель или 2.4G-донгл: там клавиатура видна как обычный USB HID и весь код работает без правок. Это не баг репозитория, это проверенный тупик (подробности в выводах ниже).

Для свечки нужна модель `sft.onnx`: возьмите её из `assets/model/` кейса.

## Протокол в двух словах

Единственный транспорт: feature report ID 6, полезная нагрузка 519 байт, все операции подкоманды по первому байту.

| Байт 0 | Операция | Зачем |
|---|---|---|
| `0x04` | setPerformance | конфиг + lightMode |
| `0x06` | setDiyLight | покраска клавиш, для реалтайма не годится: плавающая латентность |
| `0x08` | музыкальный кадр | `[8,0,0,1,0,0x7A,1]` + 126 RGB-троек. Реалтайм 25 fps, печать не лагает |

Три вывода, на которые ушло больше всего нервов:

1. Реалтайм решает канал `0x08` при lightMode 11. Вероятная механика: кадр кладётся в оверлей-буфер без блокировки опроса матрицы, тогда как `0x06` обрабатывается синхронно в главном цикле.
2. HID открывается эксклюзивно. Пока один процесс держит устройство, второй получает `0xE00002C5`. Две подсветки одновременно не погоняешь.
3. Главный грабли при отладке: упавший node оставляет осиротевший keytap с забитым stdout-пайпом, и его заблокированный колбэк тормозит всю очередь событий macOS. Печать умирает системно. Лечится `signal(SIGPIPE, SIG_DFL)` в тапе и kill ребёнка на выходе.

Поколение 2 (G75 V2, K99 V3, Ace68) умеет то же без ограничений, его 64-байтовый протокол тоже разобран, см. `experiments/`.

## Нейропредикт: числа

Модель 2-3M параметров, char-level, словарь 401 символ (заглавные RU, эмодзи, `_= @`). Полный пайплайн в `train/`, четыре ADR в `docs/adr/` объясняют каждое решение до его принятия.

| Модель | top-1 | top-3 |
|---|---|---|
| Триграмма (бейзлайн) | — | 0.916 |
| Pretrain, словарь 136 | 0.777 | 0.948 |
| SFT, словарь 401 | **0.901** | **0.955** |

Гейт проекта был ≥ +3 п.п. к триграмме на отложенном личном тексте. SFT дал +3.9. Датасет валидации личный, поэтому в репо только код и лог-числа, не данные.

Следующая ступень RL: события предикта (контекст, топ-3, что реально нажато) уже логируются, апдейты батчами по буферу. Это раздел README, который чаще всего будет дописываться.

## Кейс

`index.html` этого репо и есть GitHub Pages. Живая часть работает по-настоящему: `stand.html` грузит `sft.onnx` (3,4 млн параметров) в браузер через onnxruntime-web и на каждой введённой букве подсвечивает три ставки модели, как на живой клавиатуре. Модель идёт лениво, с прогрессом, только когда долистал до блока. Кадры-иллюстрации рисует three.js-сцена из записанных прогонов (`assets/case-data.js`), весь сторителлинг построен на реальных числах, а не на макетах.

Кейс полностью автономный: шрифты (OFL), three и ort-рантайм лежат локально, ни одного внешнего запроса. Так его можно вшить в iframe на dprofile без CSP-сюрпризов. Дизайн собирается в Open Design, экспорт отсюда.

Уроки, из которых вырос проект, лежат в `lessons/`: токен-вектор, matmul, таблицы внимания, петли генерации. Каждый читается за 5-7 минут и оперирует живыми артефактами из `train/`.

## Структура

```

train/                                             пайплайн: pretrain, sft, export_onnx

```

## Чего в репо нет и почему

- Исходники веб-драйвера MCHOSE (`rev/` в рабочей папке). Это чужой проприетарный код, публиковать его нельзя. Все знания из него переведены в таблицы этого README.
- Дампы прошивки. Тоже производное чужого продукта, плюс их официальный OTA-канал мёртв, так что устройство читается только с железа.
- Корпус. Это личные данные печати, их нет в репо. Модель `sft.onnx` наоборот, вшита в кейс как есть.

## Лицензии

Код под MIT. Шрифты кейса под SIL OFL (Geist, Science Gothic, IBM Plex Mono, Golos Text, Source Serif 4). 3D-модель кэпов в зеркале (`board3d.html`): «Mechanical Keyboard» by [Flexryhe](https://sketchfab.com/Flexryhe), лицензия Sketchfab Standard, атрибуция есть на самой странице.

## Дисклеймер

Проект не связан с MCHOSE, AULA или BY Tech. Всё сделано в образовательных целях: понять, как устроена железка, которую ты сам купил. Прикладной итог: ваша клавиатура умеет больше, чем её драйвер показывает, и для этого не нужен сниффер, достаточно исходников веб-драйвера и выходных.
